# Tech Debt Log — {PROJECT}

> Журнал технического долга: нарушения DoD, зафиксированные явно.
> Файл создаётся s0-tracker при инициализации проекта.
> Незакрытый tech debt без плана устранения блокирует следующий спринт.

---

## Правила записи

- Tech debt фиксируется ТОЛЬКО при осознанном пропуске DoD под давлением дедлайна
- Каждая запись должна иметь: нарушенный пункт DoD, причину, кто одобрил, план устранения, дедлайн
- Без плана устранения и дедлайна — запись не принимается, пропуск DoD не разрешён
- Записи со статусом OPEN блокируют `/sprint-close` если дедлайн устранения прошёл

---

## Формат записи

```
### TD-[N] — [краткое название]
- Дата: YYYY-MM-DD
- Агент: {агент-исполнитель}
- Нарушен: DoD-{N} — {описание пункта}
- Тип артефакта: Код / Документ / Инфраструктура
- Причина пропуска: {конкретная причина}
- Кто одобрил исключение: {пользователь / стейкхолдер}
- План устранения: {что конкретно сделать}
- Дедлайн устранения: YYYY-MM-DD (не позже следующего спринта)
- Статус: OPEN | IN_PROGRESS | RESOLVED
- Дата закрытия: YYYY-MM-DD
```
